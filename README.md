# CargoFusion — ACSA Prototype

A working prototype/demo of the **Autonomous Container Search Assistant (ACSA)** — an AI intelligence layer for container retrieval planning, deployed above a simulated Terminal Operating System (TOS).

This is a **prototype**, not a production terminal deployment. All TOS, IoT, equipment, and yard data are simulated. See:

- [`Autonomous-Container-Search-Assistant-Engineering-Report-Combined.docx`](./Autonomous-Container-Search-Assistant-Engineering-Report-Combined.docx) / [`report.txt`](./report.txt) — source specification
- [`docs/PROTOTYPE_IMPLEMENTATION_PLAN.md`](./docs/PROTOTYPE_IMPLEMENTATION_PLAN.md) — phased build plan and current status

## Status

Phase 2 (domain model & database) complete. See the implementation plan for current phase.

## Getting Started

```bash
npm install          # also runs `prisma generate` via postinstall
cp .env.example .env
npm run db:migrate    # creates dev.db (gitignored) from prisma/migrations
npm run dev            # http://localhost:3000
```

Other useful scripts:

```bash
npm run build       # production build; also generates Next.js's route/layout types
npm run test         # Vitest
npm run typecheck    # tsc --noEmit
npm run lint          # ESLint
npm run db:studio     # browse the local SQLite database
```

Note: `LayoutProps`/route types are generated by Next.js into `.next/types` on `dev`/`build`. Run `npm run build` (or `dev`) at least once before `npm run typecheck` on a fresh clone.

### Project Structure

```
src/
  app/                 # Next.js routes and UI (dashboard, worker view, admin)
  domain/              # Domain types (from prisma/schema.prisma) + db.ts client singleton
  adapters/tos/         # TOSAdapter interface + MockTOSAdapter (simulated TOS)
  adapters/sensors/     # SensorProvider interface + simulated IoT events
  optimization/         # Deterministic algorithms only: A*, scoring, forecasting
  agents/                # Claude orchestration: interpretation, disambiguation, explanation
  twin/                  # Digital twin state and plan validation
  events/                # In-process EventBus (Kafka stand-in)
```

See [`CONTRIBUTING.md`](./CONTRIBUTING.md) for the rules governing these module boundaries.
